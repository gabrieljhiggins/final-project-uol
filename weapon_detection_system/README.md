# Multi-Camera Weapon Detection System with Chronological Timeline

This system processes frames from multiple security cameras that started recording at **different real-world times**, runs a YOLO weapon detection model, and produces a perfectly time-synchronized dashboard for reviewing events in true chronological order.

## Features
- Handles camera segments with known start timestamps (e.g. Cam7 starts earliest, then Cam5, then Cam1)
- Correct chronological ordering across segments (fixes lexical sort bugs)
- Weapon detection (anything not "person"/"human" class)
- Per-camera annotated video frames + metadata with precise timestamps
- Global `timeline.json` of all weapon sightings
- Beautiful Flask web dashboard with:
  - Synchronized playback of all 3 cameras
  - Time slider + play/pause at ~2x speed
  - Clickable detection timeline to jump to any event
  - "NO FEED" placeholder when a camera has no coverage at current time
  - Export archive of timeline + event screenshots

## Step 1: Prepare Your Data

You need:
1. A YOLO model trained for weapon detection (`.pt` file). The model should output classes including "person" (or "human") + your weapon classes (gun, knife, etc.).
2. Extracted frames from your camera videos at **2 fps** (0.5s interval) so `frame_num * 0.5` gives correct seconds.
   - Recommended naming convention that the scripts understand:
     - `Cam1_Segment_0_frame_00042.jpg`
     - `Cam5_From09-27-50_frame_00012.jpg`
     - etc.
   - All frames can be in a single flat folder (the script auto-groups by camera + segment key).

Put all your frame images into one directory, e.g. `/data/frames/`.

Update `SEGMENT_STARTS` in `process_frames.py` if your start times differ.

## Step 2: Process the Frames (Create Timeline)

```bash
cd final-project-uol/weapon_detection_system

python process_frames.py \
    --model ../yolo26n_best.pt \
    --image_dir /Users/gabrielhiggins/Desktop/Images \
    --output_dir ../outputs
```

This will:
- Run inference on every frame (with tracking)
- Save annotated images to `outputs/annotated/CamX/frame_XXXXX.jpg`
- Write `metadata.json` per camera with exact timestamps
- Create `outputs/timeline.json` with all weapon events in chronological order

**Note**: Processing can take a while depending on #frames and GPU availability.

## Step 3: Launch the Dashboard

```bash
python app.py --port 8080
```

Open http://127.0.0.1:8080

You can now:
- Play/pause the synchronized multi-camera view
- Drag the time slider
- Click any event in the timeline table → jumps all cameras to that moment
- Download a zip with the timeline + screenshots of the first 30 events

## "Live" Camera Feeds Note

The current system is designed for **post-processing recorded footage** (best for incident review and creating a clean timeline).

For true real-time "live" feeds you would need a different architecture:
- Separate capture threads per RTSP/webcam stream
- Real-time inference queue
- Wall-clock timestamping of detections
- WebSocket push to a live-updating dashboard (or use this dashboard in "live mode" by periodically re-processing new frames)

The current chronological sync logic is still very useful as a foundation.

## Customization Ideas
- Change the weapon filter in `process_frames.py` (currently: everything except person/human)
- Adjust event cooldown (`> 1.5` seconds between logs)
- Add more cameras by extending `SEGMENT_STARTS` and the preferred display order in `app.py`
- Improve the model or add non-max-suppression / tracking refinements

## Troubleshooting
- **Wrong camera order in dashboard**: The `preferred_order` in `app.py` controls display order.
- **"NO FEED" always**: Check that `outputs/annotated/CamX/` contains `frame_*.jpg` and valid `metadata.json`.
- **Time display wrong**: The JS uses `Date` from the unix timestamps. If your processing machine and browser are in very different timezones there may be an offset — the underlying sync is still correct.
- **Missing segments**: Add their start times to `SEGMENT_STARTS` dict.
